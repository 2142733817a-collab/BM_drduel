Code for the Mount & Blade II: Bannerlord 'DR Duel' server which is a copy of the Mount & Blade Warband Duel system.  
The code was not formatted / refactored etc. since it was created out of curiosity and trying around what is possible while staying Native compatible. It was not supposed to be released at all.

Some small parts (messages / reflections) might be copied by krex his Admin tool or from takeo (cRPG).

## 服务器提示语言

部署者可设置服务器进程环境变量 `ADIMI_MESSAGE_LANGUAGE=en` 使用英文提示；不设置或设为 `zh` 时使用中文。服务器内的玩家共用该语言，无需安装客户端 Mod；修改配置后需重启服务器。详见[服务器提示语言设置](docs/服务器提示语言设置.md)。

## 1局定胜负 / 3局2胜 / 5局3胜

循环切换：给带碰撞、可被武器击中的木桶或其他物品添加一个 `adimi_duel_mode_cycle` 标签。每次敲击按敲击者当前个人设置轮换：**1局定胜负 → 3局2胜 → 5局3胜 → 1局定胜负**。默认单局，因此第一次敲击会选中3局2胜。多人共用同一物品时，各自只改变自己的设置，左下角显示选中的赛制；服务器自动挂载命中脚本，无须在编辑器里添加自定义脚本。

在木桶可被命中的本体上用新标签替换旧赛制标签，光圈及其他子物体可保持原样。不要在同一物品上混用循环标签和任何固定胜制标签，混用时不改变玩家设置。原有固定标签和行为保持不变。

固定选择仍可在场景中放置三个带碰撞、可被武器击中的物品，各选择一种胜制：

| 新地图推荐标签 | 兼容原地图标签（替换原来的三个档位） | 个人胜制 | 聊天指令 |
| --- | --- | --- | --- |
| `adimi_bo1_anvil` | `adimi_ft3_anvil` | 1局定胜负，先胜 1 局 | `!ft 1` |
| `adimi_bo3_anvil` | `adimi_ft5_anvil` | 3局2胜，先胜 2 局 | `!ft 2` |
| `adimi_bo5_anvil` | `adimi_ft7_anvil` | 5局3胜，先胜 3 局 | `!ft 3` |

原 FT3 / FT5 / FT7 三个物品按表直接换成新胜制，已有标签和 `AdimiToolsDuelFt7Anvil` 脚本类名继续识别，无须重新摆放物品。旧标签中的数字不再表示先胜数，地图里的显示文字应同步修改。新地图优先使用 `bo` 标签，物品名称不参与判断。同一物品选择多个不同胜制时禁用，同一胜制的新旧别名可共存。敲击直接选定该胜制，再次敲击仍保持该胜制；恢复单局请敲击单局物品。

玩家默认1局定胜负；`!ft` / `!firstto` 参数是先胜数，仅支持 1、2、3，不再接受 4–10。真人 1v1 双方须选择相同胜制才能发出和接受挑战，接受时锁定，本系列不能中途修改。1 对 1 AI 同样使用个人胜制，多 AI 仍是1局定胜负。多人队战按下节规则比较全部参战者的选择。

只需要服务端代码，玩家继续使用原版客户端。最新地图核对副本已收录到 `ExampleScenes/SceneObj/duel_empire_day`，编辑地形数据在 `ExampleScenes/SceneEditData/duel_empire_day`，可随本仓库一起提交。共 9 个文件，以 2026-11-05 23:44 保存的新稿为基底，保留最新地形、导航和武器架调整；当前 16 个木桶使用 `adimi_duel_mode_cycle`、4 个盾牌堆使用 `adimi_culture_cycle`。核对副本为 74 个光圈网格补回原版参数，沿用既有 4 个共享大 Box 的标签位置修正及单处 chair 兼容替换。本次只复制核对后的项目文件，没有覆盖本机运行地图或服务器；本轮修复尚未部署。部署地图时保持 `SceneObj` 和 `SceneEditData` 的相对目录结构，实际碰撞命中和显示由游戏内验证。

## 双准备区多人队战（原版客户端）

每个场地放置两个准备 `VolumeBox`（A、B），以及一个覆盖整个战斗场地的 `VolumeBox`。服务器按空间自动关联：两个小 Box 的世界中心分别落在大 Box 内即可，不要求父子挂载或相同组号。两个准备区应互不重叠、都位于全场检测盒内；不同场地应分开。同一场地可以让 AI 与队战使用同一个大 Box，配置见下文。

| 对象 | 标签 | 原版脚本 |
| --- | --- | --- |
| A 队准备 Box | `adimi_team_side_a` | `VolumeBox` |
| B 队准备 Box | `adimi_team_side_b` | `VolumeBox` |
| 全场检测 Box | `adimi_team_area` | `VolumeBox` |
| 屏障根，可有多个 | `adimi_team_barrier` | 原版 `SynchedMissionObject` |

每个大 Box 范围内必须正好有一个 A 小 Box 和一个 B 小 Box；缺少、重复、没有 `VolumeBox` 脚本或尺寸无效时禁用该场地并记日志。小 Box 中心同时落在两个大 Box 内时，相关场地均禁用，避免共享准备区。旧 `adimi_team_group_N` 标签可以保留，但不参与空间归属；大 Box 上唯一可用的旧组号仅作为内部日志编号保留，其他情况自动编号。

准备区和独立屏障只保留一个功能角色，不混用 FT、国家选择或其他交互标签；大 Box 允许下述 AI 与队战共用配置。检测盒缩放必须为正。屏障按其原点当前位置或向上 3 米后的位置关联大 Box；地下存放的屏障不需要为了检测而移到地上。屏障同时匹配多个场地时禁用相关场地。已有父子关系保留，但 A/B/场地 Box 不能挂到会升降的屏障或 AI 梯子之下。带标签屏障父根会带动子物体，不重复移动子节点。屏障保留碰撞并设为 Dynamic，保存位置为地下起点；预先挂原版 `SynchedMissionObject`，不挂服务端自定义脚本。场地、准备区和屏障关联在场景初始化时确定。

### AI 与队战共用同一场地

在同一个大 `VolumeBox` 对象上同时保留：

- `adimi_ai_area`
- 原 AI 组号，例如 `adimi_ai_group_1`（恰好一个有效组号）
- `adimi_team_area`

大 Box 保留原版 `VolumeBox` 脚本，不需要创建两个重叠 Box。AI 触发物、AI 出生点继续按原 AI 组号配置；A/B 小 Box 只保留各自 `adimi_team_side_a` / `adimi_team_side_b`，按空间范围关联。不需要给 A/B 添加 AI 组号或挂到大 Box 下。共用模式要求这个大 Box 对应的 AI 组已通过初始化；无效 AI 配置不会让队战绕过共用控制单独开局。

同一场地只有一个对局占用状态。AI 首次有效触发或双方 A/B 名单首次齐备时占用场地，直到整场结束、清理及边界复位完成才释放。AI 占用期间 A/B 不累计准备时间；开放后重新执行稳定 3 秒和倒计时 3 秒。队战占用期间 AI 敲击只提示场地忙碌，不生成 AI 或排队重放。系列赛小局之间继续占用；清理或边界同步失败时保留占用并重试，不能让另一种对局提前进入。运行中直接移除正在占用的场地行为时，不把一次延迟删除请求视为清理完成，场地保持关闭直到场景清空。

共用场地会直接沿用 AI 组已配置的升降屏障和旋转梯子，队战无需给它们补 `adimi_team_barrier`。大 Box 内额外的独立队战屏障也会加入共用边界，AI 和队战都控制这些边界。已经同时带有两套声明的同一 AI 移动层级不再创建第二个控制器；跨场地、跨 AI 组或不明确的移动层级仍按错误配置处理。空闲的另一种玩法不会清理本场角色或改变屏障。

多人队战通过左下角管理员消息提示人数、赛制、倒计时和比分，不显示顶部横幅，也没有接入原版左上角的两人对局小面板。开局 3/2/1 秒倒计时每次变化会定向请求提示音，同一倒计时数值不重复播放；局间双方准备完毕的 3 秒提示也请求一次声音，稳定名单、比分和其他普通状态消息静默。上述共用逻辑仅经过离线检查，真实地图、碰撞、梯子和联网效果需要游戏内验收。

双方各有至少一位符合条件的自由玩家即可，人数不用相等，1v5、3v2 都允许。按完整角色名单计时：双方名单连续稳定 **3 秒**后，进入 **3 秒开局倒计时**。任一阶段有人进入、退出、换边、死亡、断线或换了角色，都会回到名单稳定计时；人数相同但换人也会重新计时。一侧无人则等待，不清场、不移动屏障。

倒计时结束后锁定名单，先检查所有无关人员的区域外落点；有人属于其他对局，或缺少合适落点时取消开局，不把其他对局玩家强制搬走。检查通过后清理场内无关玩家、散落装备、尸体和无人马，补满参战玩家及其当前坐骑状态，再让屏障沿世界 Z 上升 **3 米／1.5 秒**。所有屏障成功到位后才开启两队敌对关系；没有配置屏障的组在准备完成后的下一次任务更新开战。屏障故障会取消本组并复位，失败未处理完时保留占用，其他组继续工作。

开局清除上一场个人对局遗留的一次性武器恢复记录，保留当前手持装备，避免本场阵亡后的新生命带入旧对局武器。锁定双方名单时比较**全部参战者**的个人胜制：所有人选择相同的1局定胜负、3局2胜或5局3胜，就使用共同胜制；任何人不同、缺少有效设置时都按1局定胜负，并提示原因。不会自动改写任何人的个人选择；开赛后修改个人设置只影响下一场。

队战以小局计分，一方全员出局时另一方得 1 分，先达到本场目标胜场的队伍赢得整场。双方同时全员阵亡，小局平局不加分，保持原胜制重打该小局，直到分出胜负。局间保持屏障升起，双方暂停敌对；存活者保留原角色、位置与当前武器，只补状态；阵亡者按锁定时角色、装备和本队准备区附近的有效空位复活。双方可继续人员全部准备好后友好倒计时 3 秒再开战，30 秒仍无法完成准备则取消整场。

断线、换队或越过全场检测盒边界的玩家退出整场，不能靠复活或换角色回场；一侧已无可继续玩家时提前结束整场。原名单之外的人不能加入进行中的系列。存活队友、旁观者和不同场次之间禁止互相伤害；真实武器、盾牌、远程与坐骑表现仍需游戏验证。战斗期间进入场内的无关自由玩家会被移到区域外出生点。

正常结束立即解除敌对、恢复玩家及存活坐骑的原队伍，并补满存活玩家当前状态，保留现有位置、武器和持武器动作；1 秒后屏障开始下降，3 秒后执行区域清理，并继续 1 秒处理延迟掉落物。清理及屏障复位成功后释放名单，阵亡者恢复普通出生流程。正常整场完成后，已阵亡且未退出的步兵/重步兵沿用锁定开局时的完整装备、修饰和国家旗帜快照，破盾也恢复满耐久；复活仍使用普通出生点，装备经过原版预览、正式出生和 SpawnEnd 后恢复，成功后一次消费。取消、退出、断线或换队不套用这份完成恢复记录，射手和骑兵保持原有规则。清场/结束任务立即恢复屏障原始局部变换，不读已经被原生删除的旧角色。清理失败会重试，成功的补状态不会重复执行；故障组在完成清理后禁用至场景重载。

准备名单、倒计时、战斗及清理期间，参战玩家不能进入普通决斗、AI 挑战、国家切换或传送；旧的未接受邀请在加入准备名单后取消。地图需要保留位于所有战斗/AI 检测盒外的普通 `spawnpoint`，并正确设置 `exclude_mounted` / `exclude_footmen`。玩家无需客户端 Mod，通知与对战均走原版接口；地图摆放、碰撞、网络及实机验收由用户完成。

## 复活与区域引导（原版客户端）

实际玩家每次复活后，按新角色的兵种显示对应方向和操作提示：射手前往北方、骑兵前往南方、步兵及其他默认兵种使用中心区域。骑射按骑兵处理，与出生点分类一致；按实际复活角色判断，不因尚未生效的选兵菜单或临时换武器改变提示。

地图中下列两个提示 Box 需要挂原版 `VolumeBox` 脚本；只有 `volume_box` 网格和标签不能执行范围检测：

| 提示区域 | 原有标签 |
| --- | --- |
| 射手区 | `Sagittarius_Tip` |
| 骑兵区 | `Horse_Cavalry_Alert` |

所有兵种均可进入对应 Box 阅读方向提示，离开后再次进入会重新提示；站在区域内不会持续刷屏。重叠同类提示 Box 按同一提示区域处理。任意带 `adimi_ai_area` 或 `adimi_team_area` 的大 Box 会显示 AI 数量和难度、多人准备区、武器旁木桶切换1局定胜负/3局2胜/5局3胜及多人赛制一致性规则；共用大 Box 的双标签不会发送两遍。同一角色的出生提示与同类区域提示同时发生时合并；死亡、换角色、断线或场景清空会丢弃旧的待发提示。

规则定向发送给该玩家，使用原版普通聊天消息，按现有文本宽度和真实换行显示在左下角。每个 `【标题】` 使用原版 `HeadshotTitle.Text` 亮紫红样式，正文保留白色，不加入管理员前缀或顶部公告，不按阅读时长排队。每位玩家在本场景首次选兵实际复活，以及新进入场地触发玩法规则时，请求一次独立定向提示音；同次检测最多一声。后续普通复活和射手/骑兵方向 Box 重入静默。原版当前聊天样式不支持服务端指定多套标题/浅色正文或取消阴影，这些需要客户端界面资源，本轮未加入。真实颜色、音量和声音表现留给实机验收。

AI 挥砍预约和增加人数提示使用普通左下角聊天：`【生成AI】3秒后生成X名…`，不带 `[Admin]`；标题连同括号、实际生成数量 X 使用上述紫色样式，其余正文白色。持矛模式中的 `继续挥砍可增加人数（最多10）` 整段也为紫色。每次有效命中更新当前数量并保留独立定向声音，不进入顶部 QuickInformation 横幅队列。其他 AI 状态保留原管理员消息通道；玩家整场获胜时不再发送“AI 系列结束/你获胜”通知或对应提示音，原比分、奖励、回血和延迟清理仍照常执行，失败和取消提示保留。文字发送成功后才请求音效；没有有效存活角色时仍发文字、跳过声音。原版服务端协议不能撤回已经进入客户端队列的旧横幅。原生小对局信息面板沿用原流程。

## 物品标签切换国家（原版客户端）

循环切换：在可命中的物品本体上添加一个 `adimi_culture_cycle`。当前地图四个 `prop_merchantweapons_shield_c` 盾牌堆已添加此标签，原预制体已有碰撞，无需拆分盾牌。每敲一次，从该玩家当前待选国家继续轮换；没有待选项时从实际国家继续。顺序为帝国 → 瓦兰迪亚 → 斯特吉亚 → 巴旦尼亚 → 库赛特 → 阿塞莱 → 帝国，跳过未加载国家。左下角管理员消息预告 `3 秒后切换至…` 并请求声音；连敲刷新选择和 3 秒计时，不提前切换。不同盾牌堆共用该玩家的待选状态，不同玩家互不影响。

固定选择：在自己的地图里放置有武器命中碰撞、不会被打坏的独立物品，例如雕像、铁砧或旗杆；给每个物品添加下表中的**一个**标签。循环标签与固定国家标签不混用。实体名称和外观不决定国家，可以自行摆放国家旗帜作为可视提示。

| 国家 | 物品标签 |
| --- | --- |
| 帝国 | `adimi_culture_empire` |
| 瓦兰迪亚 | `adimi_culture_vlandia` |
| 斯特吉亚 | `adimi_culture_sturgia` |
| 巴旦尼亚 | `adimi_culture_battania` |
| 库赛特 | `adimi_culture_khuzait` |
| 阿塞莱 | `adimi_culture_aserai` |

玩家靠近敲击物品后先收到提示，**3 秒后**服务端才让原版客户端关闭旧预览、同步国家并重新生成选兵预览。等待期间再次敲击，以最后一次选择为准，重新计时 3 秒；敲击同一国家也会重新计时。倒计时期间不会提前清理武器、修改国家或移除角色；不另加切换后的 3 秒冷却，原版 perk 信息未同步完成前仍不能再次选择。下方列表使用该国完整多人兵种、perk 和装备，选好后按界面提示重生；选择当前国家也能重新进入选兵。实际应用时会移除当前玩家和坐骑，使用新兵种的初始装备，不保留武器架或上一场真人决斗的武器恢复记录。

仅自由区玩家可切换；自己发出的未答真人邀请、准备/交战/结算/FT 重赛、AI 预约/训练/结束清理及待完成的 AI 复活都会阻止切换。等待期间每次任务更新重新检查：进入真人、AI 或多人队战、死亡、断线、换队、换角色或选装未就绪会取消待切换；即使后来恢复空闲，也不会自动重放旧选择。收到的未接受邀请在成功应用切换时取消，原版客户端旧提示按原有期限消失。远处射击和 AI 命中不触发。任务重置会丢弃待切换，静态标签观察器在重置完成后重新绑定。

每个实体只放一个国家标签，不与 AI、FT 铁砧、武器架、传送门等交互标签混用。不要在地图里挂服务端自定义脚本；服务器自动添加命中观察器，不需要增加客户端 DLL 或同步对象 ID。标签必须在实际被武器命中的有碰撞实体上；仅有无碰撞的飘动旗布不保证能命中，必要时给下面的旗杆/基座加标签。未知国家或冲突标签会跳过并记录日志。代码从已加载且有多人兵种的国家中解析 ID，本机原版数据为上表六国、每国 7 个多人兵种；不包括单人战役兵种。

此功能不在选兵页顶部增加新按钮。地图由用户摆放和保存；需要更新后的服务端代码及含标签的地图才会生效，实际命中、界面刷新与重生效果仍需游戏验收。

王国徽记不会因国家标签而自动绘制。按用户当前决定，`prop_merchantweapons_shield_c` 组合盾牌架保持原样，不做按材质随机贴国徽，也不替换成重新布置的独立盾牌展示架。

## 原版客户端的距离决斗提示

服务器默认每 0.5 秒检查一次距离：超过 80 米隐藏头顶决斗提示，靠近到 75 米以内恢复。75–80 米之间保持上次状态，减少边界反复切换。每次每名观察者最多处理 8 个变化，优先恢复靠近的目标；距离未变化到需要切换时不重复发消息。

玩家不需要安装客户端 Mod。服务器只向对应观察者发送原版消息，使用临时个人对局状态的覆盖与结束来保留目标隐藏缓存，不新增虚假进行中对局行，不改变真实 Team、生命值或位置。每条消息使用独立可靠事件；不能保证原版客户端把整组消息在同一帧显示完毕。

正在准备、进行 FT 系列或有待处理挑战的观察者暂停更新；真实对局中的目标不会因靠近而恢复提示。真实系列结束后重新计算其提示状态；重连和断线会清理对应观察关系。发送异常时停止新的距离更新，并在观察者空闲后尝试恢复原版提示，失败会记入服务器日志并等待下次清理。

AI 预约和训练不属于原版真人决斗消息流程，单独接入隐藏策略：AI 挑战者作为目标时，对其他观察者隐藏头顶决斗信息；作为观察者时，也隐藏周围玩家的可挑战信息。倒计时和 FT 局间保持隐藏，结束后附近目标恢复、远处目标仍按距离隐藏。隐藏机制本身不新增对局条目；实际 AI 挑战另外使用下述独立显示记录。

当前实现保守接受 `area_flag_1` 到 `area_flag_5`（使用编号 0–4）；没有这些有效场地编号时功能自动停用。这不是协议上限：原版该字段为 4 位，可编码 0–15。这里的场地编号与传送门编号 1–20 是不同用途。

设置服务器进程环境变量 `ADIMI_DUEL_DISTANCE_MARKERS=0` 可在下次载入场景时关闭此功能。当前代码验证不包含游戏运行；消息分帧时是否闪出个人面板、多人场景下开销及完整联机效果仍需实际客户端验收。

触发物需要可被武器打击的实体碰撞。服务器自动挂载命中观察器，地图内不需要挂本 Mod 的自定义脚本，也不需要玩家安装客户端 DLL。不要同时保留 FT 铁砧、传送门标签；推荐普通非破坏性物品，避免子实体脚本抢占命中。AI 标记使用独立箭头/空实体，不能带普通玩家出生用的 `spawnpoint` 标签；标记附近需要可行走的 AI 导航网格和足够站位。

敲击一次预约本组并提示 3 秒后生成 1 个 AI；同一玩家继续有效敲击时增加数量，并从最后一次有效敲击重新倒计时 3 秒。0.25 秒内重复命中按一次处理，每次最多 10 个 AI。简单、一般使用首次敲击时玩家的装备快照和相同角色，包含武器架取得的武器与当前坐骑；不套用 21 套自定义配装，避免覆盖玩家装备，也不是完整复制所有玩家特长效果。困难使用上表固定模板。AI 拥有独立装备，只与触发者敌对、锁定该玩家，不与同组 AI、路人或其他组玩家敌对。

收到尚未接受的真人决斗邀请仍可触发 AI。首次成功预约会移除该玩家收到的服务端待处理邀请；原版客户端旧提示按其 10 秒期限消失，迟到接受不会开启真人对局。自己主动发出的未答邀请，以及已经进入准备、交战或 FT 系列的真人对局仍会阻止触发 AI；一个玩家仍不能同时预约多个 AI 组。

**AI 对局规则：1 对 1 沿用玩家选择的1局定胜负、3局2胜或5局3胜（物品或 `!ft 1 / 2 / 3`）；1 对 2 个及以上 AI 强制1局定胜负。** 规则在首次生成 AI 时固定，系列中修改个人设置不影响正在进行的系列，也不会为了多 AI 对局改写玩家个人设置。多 AI 局必须击败全部 AI 才算玩家获胜，击败其中一个不会结束；玩家先阵亡则整局失败，同时死亡也按玩家失败结算。

实际 AI 挑战会向空闲旁观者的原版左上对局列表发送显示记录：`[AI简单] 兵种 ×N`、`[AI一般] 兵种 ×N` 或 `[AI困难] 兵种 ×N`，同时更新 FT 比分。显示身份使用独立非真人 ID，不加入服务器真人列表、不挂实际 AI，结束后移除组件和条目；仍需有效的 `area_flag_1` 至 `_5`。挑战者自身保留训练文字提示，避免与隐藏头顶标记的个人面板消息冲突。此功能只使用原版客户端已有消息，当前已进行托管方法和状态回归，完整网络时序及实际 UI 留待实机验证。

AI 挑战计入原版击杀与阵亡，训练逻辑不重复累计。整场胜利另按原真人决斗公式结算一次决斗积分、连胜和赏金；FT 中间局和多 AI 单个击杀不重复结算。失败保留累计积分、清连胜及赏金，三档没有额外积分倍率。取消、断线、换场不计完成；服务器保存逐场日志，未新增数据库长期战绩功能。AI / PvP 共同限制协议不能表示的分数与连胜，正常范围内的奖励公式不变。

1 对 1 的 FT 系列每局单独计分，未达到目标胜场时**只复活败者，保留胜者实体和当前位置**：玩家阵亡时，存活 AI 及其坐骑保留，玩家通过原版流程在本组出生标记处复活（普通区为 `adimi_ai_spawn`，独立矛兵区为 `adimi_ai_spear_spawn`）；AI 阵亡时，在该标记处生成替代 AI，存活玩家留在当前位置，不拉回首次敲击点。点位被活体占用时选择标记附近有效导航位置，不移动幸存者。双方准备好后，按原服恢复函数补生命、盾牌、箭和弩矢，再友好等待 3 秒后继续交战。等待期间保留区域占用及升起的障碍物，存活 AI 暂停锁定旧玩家，开局时改为锁定复活后的新玩家角色。

玩家复活仍使用本次训练的角色和装备快照，位置优先于普通按兵种/分区出生点；原来的 AI 出生标记直接复用，不增加必需组件。30 秒内未完成复活则取消系列。同时死亡按玩家本局失败计分，两方均死亡时在玩家回来后补出 AI，再共同等待 3 秒。只有整场胜负已定或挑战取消时才清理本组存活 AI、释放区域、下降障碍物；检测区域内的尸体按下述开局/结束清理规则处理，整场结束的本组 AI 清理时序见下段；普通尸体保留 10 秒消失配置。

整场 AI 挑战分出胜负后，存活玩家保持原实体、位置、当前装备、持武器及挥刀状态，只按战前生命上限回满血，补满当前盾牌和弹药、恢复当前坐骑生命；不重新装备或切换到初始武器。正常整场结束时立即解除敌对、结算成绩并补满状态，1 秒后开始复位阻挡物（移动仍耗时 1.5 秒），3 秒后清理本组 AI、AI 坐骑和区域散落物/尸体；没有 Box 的组也清理本组 AI。结束延迟期间禁止同组或同一玩家开启新挑战，清理重试不重复结算、回血或重置计时。被活人骑走的 AI 马保留给当前骑手。整场失败且已经阵亡时，自动通过原版流程在对应兵种的普通重生点满状态复活：步兵/重步兵保留首次敲击时当前全套装备快照，包含武器架取得的武器，期间破碎的盾牌也从快照恢复并补满耐久；射手和骑兵继续使用首次敲击时角色、所选 perk 与外观对应的兵种初始装备及国家旗帜。骑兵按初始装备生成新坐骑，不复用训练坐骑的创建标识。整场完成复活所需装备在预约时单独保存，预览、正式出生及原版 SpawnEnd 后的补装使用同一份快照，避免出生过滤或回调改写导致装备缺失。装备恢复成功后才消费完成记录，失败每秒重试且不重复回血；已生成角色的装备重试不会再次创建预览或角色。该完成复活记录不使用 FT 局间的 30 秒超时；断线、换队、死亡、其他生成与清场会使旧记录失效。未结束的 FT 局间败者复活继续使用训练装备快照并保留胜者实体；取消、断线、换队与场景清理不伪装成挑战完成。

障碍物如有设置，需在场景中预先挂好原版 `SynchedMissionObject`（不是城门/可破坏物的派生脚本），设置为可移动的动态实体并保留有效碰撞。地图保存的位置就是地下起始位置。首次敲击后沿**世界 Z 轴向上 3 米，耗时 1.5 秒**；整场对局/FT 系列结束（包含越界判负）时，等待 1 秒再从当前位置用 1.5 秒回到保存的起点；挑战者断线、换队等取消则直接开始复位。复位和结束清理期间不能再次预约。不要给障碍物挂服务端自定义同步脚本或手工修改对象 ID。

**旋转放倒梯子的配置示例：** 给梯子加 `adimi_ai_ladder` 和 `adimi_ai_group_5`，挂原版 `SynchedMissionObject`，设置为动态实体。梯子保存时放在正常可爬的位置，物体原点作为固定梯脚。首次敲击后在 **1.5 秒**内由保存姿态旋转到指定放倒姿态，世界位置保持不动；本次目标数据是编辑器角度 `(X=89.43°, Y=-7.20°, Z=7.08°)`，对应截图中的第5组梯子。地图配置副本的正常姿态是 `(-30.02°, -0.08°, -0.17°)`，不会自动推算水平角度。该目标姿态是本模板的配置数据，其他朝向的梯子应先配置自己的目标数据，不能直接沿用。

整场胜负已定后延迟 1 秒，或挑战取消后立即开始，用同样1.5秒沿原旋转路径返回；结束时重放保存的完整原始局部变换，恢复位置、朝向和缩放，不累计偏移。FT小局和局间复活不提前立起梯子，恢复完成前不能再次预约。作为替代入口时，原木板及子空气墙可保留，但应移除该入口对应的AI移动标签；其他入口的木板围挡和检测盒继续使用原有规则。中间帧按两端旋转插值，不逐项插值欧拉角，也不把梯子平移到地下。

服务器在梯子首次收起前递归添加原版 `Moveable` 物理标志，保留其 `Ladder` 等既有标志，不启用刚体重力模拟。使用原版消息同步物理标志；晚加入时另定向重申已准备梯子的标志，当前位置仍走原版对象帧同步。地图必须预先有原版同步脚本和稳定场景 ID，服务器不临时补同步脚本；玩家不需要额外客户端 Mod。

同组父子或祖孙障碍都带相同标签时，只移动最上层已标记的父物体，后代保持原有局部位置、旋转和缩放随父级整体移动；子物体不会再单独上升 3 米。父根须有上述原版同步组件，子物体可以保留已有脚本，也可以仅作为普通网格/碰撞子物体。不要把同一移动层级分配给不同训练组。

梯子父子同时标记时也只旋转最高标记根一次；不要在同一移动层级混用上升障碍与旋转梯子角色，两种运动模式或不同组号的嵌套会停用相关组并记录诊断。多个独立梯子可以同组一起动作，但须使用适合各自朝向的目标姿态。

同组多个互不包含的障碍父根会一起升降，每个根独立保存原始变换、计时与重试状态。只有所有障碍完成复位后才允许再次预约。日志记录去重后的根数和随父移动的重复标签数量；不会自动补脚本、改变父子关系或修改地图。

3 米指对象原点从保存位置上移的距离。运动由服务端按 1.5 秒计时，只插值世界 Z，保持 X/Y 和地图保存的旋转、缩放矩阵，不使用 OverTime 消息。最多每 0.05 秒通过原版局部帧接口同步一次；有父对象时，先把目标世界变换转换到父对象的局部坐标，避开已核验 v1.4.8 全局帧消息的 S/F 轴读写顺序错误。最后精确到达目标后停止发送；中途反向则从当前高度移回目标。日志记录起点、目标、终点 XYZ 及完整姿态轴，供实机核对。原版客户端仍使用其原生消息处理和显示流程，不需要客户端 Mod。

区域如有设置，使用原版 `volume_box` 完整对象，保留 `VolumeBox` 脚本，调整范围覆盖挑战区域、触发者和 AI 标记。AI 初次开局和 FT 每局正式开始时，将盒内所有未触发本组的普通玩家移到所有 AI 区域之外的 `spawnpoint`，包括骑乘者；主人保持原位。先验证全部目标点，再执行搬移；缺少符合骑步限制的区域外出生点则取消新挑战，不开始混场战斗。另一场真实 PvP/AI 的参与者不被强行搬走，发现占场则取消本次开局。仅收到邀请不算正在对局，不会让旁观者免于清场。没有 Box 的最简组不执行清人。

开局清场之后，实际交战中仍按旁观者到最近参战玩家/AI 的三维距离判定：3 米内警告、1 米内移至区域外复活点，警告最多每 5 秒一次；不会因远处玩家仅仅进入或靠近 Box 就持续遣返。预约倒计时和 FT 友好等待不持续清场。机器人、坐骑不单独作为旁观者；骑乘玩家搬移时保留并移动当前坐骑，脚本交互会先停止。地图必须保留区域外有效出生点。人与人决斗使用相同 3 米警告、1 米遣返规则。

**AI 挑战开始后，存活的触发者离开本组检测盒子，直接判整场挑战失败，清理本组 AI 和 AI 坐骑并降下障碍物，不继续下一局。** 服务器沿用每 0.25 秒的区域检查；FT 局间倒计时及复活后的准备时间也受此规则约束，越界优先于同次检查中的 AI 死亡结算。判负不伪造双方已赢局数，也不修改玩家个人 FT 设置；死亡角色或等待复活的旧尸体不参与越界判定。首次生成 AI 前的 3 秒预约期离开区域只取消预约。没有区域对象时不执行这些区域检查。

**仅有触发物和 AI 出生标记、同时没有障碍物和检测盒子的组**，另用导航网格防止脱离战斗：挑战中玩家连续 5 秒离开有效 AI 导航网格，整场自动判负并清理本组 AI，提示“你已连续 5 秒脱离 AI 索敌范围，本次挑战自动判负。”回到有效网格后计时清零，死亡或等待复活不累计；FT 局间存活玩家仍需遵守。只要配置了障碍物或检测盒子中的任意一个，就不启用这条规则。不需要增加地图标签或组件。

配置检测盒子后，首次开局、FT 小局结束及再开局、挑战取消时，以及正常整场结束的 3 秒后，清理本组盒子内的散落装备、尸体和无人骑乘的马；保留所有存活角色、手持装备、正在骑乘的马和地图武器架。清理后一秒内继续短暂扫尾，处理尸体淡出后产生的掉落物；实际交战中及整场结束的前三秒暂停后台扫尾，避免提前清除 AI 尸体；单项清理失败会重试，失败未处理完时不开始新局。没有检测盒子时不执行区域清理，不使用全场景删除接口。

本项目使用的原版 Custom / Community 专服大厅保留原有服务逻辑，并按角色实体对死亡回调去重，避免清尸体再次扣减 AI 存活数、重复计算击杀或助攻。其他扩展替换了大厅类型时保留其组件，尸体回退到原生 10 秒寿命，散落装备和无人马的区域清理仍继续。

同一玩家不能同时预约多组或参加 PvP。每组复用自己的玩家/AI 私有队伍，结束后恢复玩家及原坐骑的队伍；失败的清理步骤保留引用并重试。AI 及其坐骑在取消时清理；区域内尸体由对局边界立即清理，其他尸体仍使用本决斗场景的 **10 秒消失设置**。这不会要求修改 Native 模块或安装客户端 Mod。

当前仅完成编译、离线行为和接线检查，真实命中、导航、AI 战斗、动态碰撞、原版客户端提示及联网同步需实机验收。场景和游戏安装目录未自动修改。

## 构建

使用当前 Bannerlord Dedicated Server 的 DLL，设置 `MB_SERVER_PATH` 后构建整个 `AdimiDuel_Server.sln`。默认构建仅输出本地文件，不再自动覆盖专服目录；只有显式指定 `DeployToBannerlordServer=True` 才复制模块文件。`BannerlordValidationBuild=True` 模式禁止部署，并要求将输出和中间文件指向专服之外的绝对路径。
